# FullMoney 理財試算（網頁版）

以 **Java 17** 開發的響應式（RWD）理財試算網站，手機、平板、電腦都能使用。
計算邏輯沿用桌面版 FullMoney 1.4.0 的 `service` 與 `bean`（複利試算另外加入「原始本金」，其餘未修改公式），不含桌面版的大樂透分析；另外新增「樂透投資」頁籤，試算定期買彩券的回報率。

**線上版（GitHub Pages）：<https://snick911.github.io/fullCalMoney/>**

同一份程式有兩種執行方式：

| 方式 | 計算在哪裡 | 用途 |
| --- | --- | --- |
| Java 伺服器（`run.bat`） | Java 後端，網頁呼叫 `/api/...` | 本機使用、自行架站 |
| GitHub Pages 靜態網站 | 瀏覽器，由 TeaVM 把同一份 Java 試算程式編譯成 `js/engine.js` | 免費公開網址，不需要伺服器 |

## 功能

| 分頁 | 內容 |
| --- | --- |
| 複利試算 | 原始本金（第 1 年年初投入一次）、每年固定投入金額、每年額外增加投入（第 2 年起每年多投入固定金額）、年利率與年數，試算逐年累積財富 |
| 複利試算（浮動） | 同上，但「每年額外增加投入」與「期望年利率」改為最低～最高區間，每年在區間內隨機取值（年利率取到 0.01%、可為負數；金額取到元）。按「重新計算」或修改條件都會重新產生亂數 |
| 房貸計算 | 本息／本金平均攤還、寬限期、分段利率、提前還款（縮短年限或降低月付），列出每期攤還明細 |
| 債券計算 | 持有到期的配息、總報酬率、到期殖利率（YTM）、年化報酬率；外幣債券換回台幣的報酬與匯兌損益 |
| 貨幣投資 | 透過新台幣換算兩種幣別（可一鍵交換），可線上取得最新參考匯率；轉換結果依序存多筆定存（每筆 1～12 個月，利率與到期後本息續存或本金續存各自設定），到期本息以預估匯率換回指定貨幣，算出利息、匯兌損益、總報酬、年化報酬率、損益兩平匯率，並列出到期匯率上下變動時的報酬 |
| 投資計畫 | 輸入投資本金、每月固定投資金額、每月浮動投資金額（最低～最高）、年數＋月數、期望獲利金額，算出需要的年化報酬率與浮動投資上下限的影響，列出所有可以達成的方案（例如債券、股票都可以時兩個都列）、資產配置（定存／公債／公司債／股票每 5% 一級、股票再分 5 個等級共 2,030 種組合，近似篩選後以蒙地卡羅模擬 500 種市場走勢算出達成機率，四種資產分別模擬並彼此連動，保守型／穩健型／積極型各挑一個最佳配置）、模擬設定（目前年齡、固定比例／接近期滿逐年降低股票／年齡法則、再平衡方式、常態或厚尾分布、金融海嘯／升息循環／長期盤整壓力測試、中途提領）、策略比較與壓力測試表、調整建議、累積財富走勢圖與期滿金額區間圖（手寫 SVG，滑鼠／手指移動顯示數值），以及三種配置各自的逐年試算（資產配置圓餅、四種資產的金額與獲利，對照目標進度） |
| 樂透投資 | 選擇今彩539、大樂透或威力彩，輸入每次買入金額、買入頻率（每期／每週／每月）與年數，依各獎項的中獎機率與獎金算出期望回報率（稅前與扣 20.4% 稅後）、總投入與平均虧損；換算只靠同一個獎項要中幾個才回本（例如頭獎 1 個、參獎 6 個）與中到這麼多個的機率；列出各獎項的機率、獎金、每注期望值與期間內預計中獎次數，模擬 2,000 人照同樣方式買的結果（中位數回報率、沒有虧損的比例），並對照同樣的錢改成定期投資的金額。大樂透、威力彩可輸入當期頭獎金額 |

- 條件一改就自動重算，計算全部在 Java 後端執行。
- 金額欄位離開時自動補千分位，並顯示「萬／億」換算；可輸入全形數字。
- 複利、債券、貨幣投資有「金額不顯示小數（四捨五入）」選項，預設勾選。由 Java 端從完整數值四捨五入到整數（`HALF_UP`），不會先進位到小數兩位再進位；百分比不受影響。房貸本來就四捨五入到元，沒有這個選項。
- 輸入不合理時（例如寬限期不短於年限），欄位標紅並顯示原因，上一次的結果淡化保留。
- **保存試算條件**：每次試算都會把各分頁的條件（含房貸清單、浮動試算的亂數種子）存到瀏覽器的 localStorage，下次開啟時自動還原並重算，看到的就是上次的結果；網址沒有指定分頁時回到上次的分頁。按「恢復預設」回到預設值。詳見下方「資料保存」。
- **外觀設定**（右上角「外觀設定」）：
  - 主題色系 6 種：淺色、護眼暗色、深色、護眼米黃、海洋藍、櫻花粉。
  - 字體大小 4 段：小（14px）、中（16px）、大（19px）、特大（22px）。版面全部以 rem 計算，字體放大時欄位會自動減少欄數。
  - 設定保存在瀏覽器（localStorage）。第一次開啟時依系統的深淺色模式選擇「淺色」或「護眼暗色」。

## 快速開始

Windows 直接執行 `run.bat`，會編譯、打包並啟動，然後用瀏覽器開啟 <http://localhost:8080/>。按 `Ctrl+C` 停止。

手動建置與啟動（PowerShell）：

```powershell
javac --release 17 -encoding UTF-8 -d target\classes (Get-ChildItem src\main\java -Recurse -Filter *.java).FullName
Copy-Item src\main\resources\* target\classes -Recurse -Force
java -cp target\classes com.fullmoney.WebApp
```

`build.bat` 會另外產生可單獨執行的 `target\fullcalmoney.jar`：

```powershell
java -jar target\fullcalmoney.jar
```

### 監聽位址

| 系統屬性 | 環境變數 | 預設 | 說明 |
| --- | --- | --- | --- |
| `-Dport=9090` | `PORT` | `8080` | 連接埠 |
| `-Dhost=0.0.0.0` | `HOST` | `127.0.0.1` | 預設只有本機可連。要用同一個網路的手機測試 RWD，或部署到伺服器時改為 `0.0.0.0` |

例如讓手機連線測試：

```powershell
$env:HOST = '0.0.0.0'; java -jar target\fullcalmoney.jar
```

手機瀏覽器開啟 `http://電腦的區網 IP:8080/`。Windows 防火牆第一次會詢問是否允許 Java 連線。

- 伺服器與瀏覽器端引擎共用的 `ApiEndpoint.execute`：正常結果、錯誤欄位、千分位格式。

## 專案結構

```text
src/main/java/com/fullmoney/
├─ WebApp.java              進入點，啟動網站
├─ AppVersion.java          名稱與版本號（頁尾與 /api/meta 由此取得）
├─ bean/                    沿用桌面版：複利、房貸、債券的條件與結果
│                           新增：InvestmentTier（投資計畫的標的類別與報酬率假設）、AllocationProfile（資產配置類型）、InvestmentPlan（投資計畫結果）、
│                           PlanSettings（模擬設定）、GlidePath／RebalanceMode／ReturnDistribution／StressScenario／StressTiming（模擬設定的選項）、
│                           LotteryGame／LotteryPrize（三種彩券的價格、獎項與獎金規則）、LotteryPrizeValue、PurchaseFrequency（買入頻率）、
│                           TimeDeposit／TimeDepositPeriod／TimeDepositResult／DepositReturn／DepositRollover（貨幣投資的定存）
├─ service/                 沿用桌面版：MoneyCalculator、MortgageCalculator、BondCalculator、CurrencyConverter
│                           新增：FloatingMoneyCalculator（浮動複利）、RangeRandom（可重現的亂數，SplitMix64）、InvestmentPlanner（投資計畫）、
│                           MarketSimulator（多資產蒙地卡羅模擬）、Allocation（配置的逐年比例與再平衡）、CashFlows（投入與中途提領）、
│                           LotteryCalculator（彩券回報率與中獎模擬）、TimeDepositCalculator（依序定存與換回後的報酬）
└─ web/
   ├─ ApiEndpoint.java      一個 API：參數 → 結果，不依賴 HttpServer，伺服器與瀏覽器端引擎共用
   ├─ ApiHandler.java       把 ApiEndpoint 接到 HttpServer：路徑、請求方式、錯誤紀錄
   ├─ WebServer.java        建立 HttpServer、註冊路徑
   ├─ Params.java           表單參數解析與範圍檢查
   ├─ Json.java / Numbers.java   最小 JSON 輸出、千分位格式
   ├─ StaticHandler.java    從 classpath 提供網頁檔（副檔名白名單、ETag）
   ├─ Http.java             回應標頭（CSP 等安全標頭）、gzip
   └─ api/                  ApiEndpoints（清單）、CompoundApi、FloatingCompoundApi、MortgageApi、BondApi、CurrencyApi、PlanApi、LotteryApi、MetaApi
src/main/resources/static/
├─ index.html               各分頁的版面
├─ css/app.css              主題色系、字體大小、RWD
├─ js/boot.js               畫面繪製前套用主題與字體，避免閃爍
├─ js/app.js                即時重算、外觀設定、分頁切換、保存與還原試算條件
└─ js/engine.js             伺服器版的空殼；Pages 建置時換成 TeaVM 編譯的試算引擎
src/pages/java/com/fullmoney/pages/BrowserEngine.java   Pages 版的瀏覽器端引擎（只在 Maven pages 設定檔編譯）
src/test/java/com/fullmoney/CalculatorCheck.java         自我檢查
.github/workflows/pages.yml                              推送到 main 時自動部署 GitHub Pages
build.bat / run.bat / test.bat                           不需 Maven 的建置、啟動、檢查
```

分層原則與桌面版相同：`service`、`bean` 不知道網頁的存在，`web` 只負責轉換輸入與輸出。

`ApiEndpoint` 與它呼叫到的類別（`web.api`、`Params`、`Json`、`Numbers`、`service`、`bean`）也會被編譯成 JavaScript，只能使用 TeaVM 支援的 Java 類別：不要用 `java.text`（`NumberFormat`、`Normalizer`）、`String.format`、`Locale` 與反射（例如 `Enum.valueOf`）。不確定時執行一次 Pages 建置，不支援的類別會在編譯時報錯。

## GitHub Pages

推送到 `main` 後，GitHub Actions（`.github/workflows/pages.yml`）會：

1. 執行自我檢查。
2. `mvn -P pages clean process-classes`：TeaVM 把 `BrowserEngine` 與試算程式編譯成 ES 模組 `target/pages/js/engine.js`，並複製網頁檔到 `target/pages`。
3. 部署到 <https://snick911.github.io/fullCalMoney/>。

網頁載入時用 `import('./engine.js')` 取得引擎：Pages 版有 `call` 函式就在瀏覽器計算；伺服器版的 `engine.js` 是空殼，改呼叫 `/api/...`。兩者的輸入與結果格式完全相同。

本機產生靜態網站（需要 Maven 3.9 以上）：

```powershell
mvn -P pages clean process-classes
```

`target/pages` 必須透過網頁伺服器開啟，直接雙擊 `index.html`（`file://`）時瀏覽器不允許載入 JavaScript 模組。

第一次部署前要在 GitHub 專案的 **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。

## API

接受 `POST`（`application/x-www-form-urlencoded`）或 `GET`（查詢字串），回傳 JSON。百分比欄位都以「%」輸入，例如年利率 2.2。

| 路徑 | 參數 |
| --- | --- |
| `GET /api/meta` | 無。回傳版本號、下拉選單選項（幣別與範例匯率、配息頻率、還款方式、提前還款方式、定存續存方式等） |
| `/api/compound` | `initialAmount`（原始本金）、`baseAmount`（每年固定投入金額）、`rate`、`addAmount`（每年額外增加投入）、`years` |
| `/api/floating` | `initialAmount`、`baseAmount`、`addMin`、`addMax`、`rateMin`、`rateMax`（-100～100）、`years`、`seed`（0～999,999,999，相同種子結果相同；不送時隨機產生，回傳的 `seed` 為實際使用的種子） |
| `/api/mortgage` | `loanAmount`、`rate`、`years`、`graceYears`、`method`、`prepaymentMode`；分段利率以 `ratePeriod` + `rateValue` 成對重複送出，提前還款以 `prepayPeriod` + `prepayAmount` 成對重複送出 |
| `/api/bond` | `currency`、`faceValue`、`buyPrice`、`redemptionPrice`、`couponRate`、`frequency`、`years`、`feeRate`、`taxRate`、`buyExchangeRate`、`couponExchangeRate`、`redemptionExchangeRate`（新台幣不必送匯率） |
| `/api/currency` | `amount`、`from`、`fromRate`、`to`、`toRate`（新台幣不必送匯率）。定存（選填，最多 120 筆）：`depositTerm`（存期 1～12 個月）+ `depositRate`（年利率 %）+ `depositRollover`（到期後：`COMPOUND` 本息續存、`PRINCIPAL` 本金續存；最後一筆不影響結果）每筆一組重複送出，依順序接續；沒送 `depositRollover` 時每筆都用 `rollover`（預設本息續存）；`settle`（換回貨幣，預設同 `from`）、`settleRate`（到期預估匯率：1 單位 `to` 可換多少 `settle`，兩者相同時不必送）、`settleNowRate`（`settle` 目前 1 單位可換多少新台幣，只有 `settle` 不是 `from`、`to` 或新台幣時需要）。沒有定存時 `deposit` 為 `null` |
| `/api/plan` | `principal`（投資本金，可為 0）、`monthlyFixed`（每月固定投資）、`floatMin`／`floatMax`（每月浮動投資區間；這三個選填，預設 0）、`years`（0～100）、`months`（0～11，合計至少 1 個月）、`profit`（期望獲利金額） |
| `/api/lottery` | `game`（`DAILY_CASH` 今彩539、`LOTTO` 大樂透、`SUPER_LOTTO` 威力彩）、`amount`（每次買入金額，至少一注）、`frequency`（`EVERY_DRAW` 每期、`WEEKLY` 每週、`MONTHLY` 每月）、`years`（1～80）、`jackpot`（頭獎金額，選填，只用於大樂透與威力彩，不可低於保底）、`compareRate`（對照的定期投資年報酬率 0～30） |

`/api/compound`、`/api/floating`、`/api/bond`、`/api/currency`、`/api/plan`、`/api/lottery` 可另外送 `round=1`，金額四捨五入到整數；不送時到小數兩位。回傳的 `decimals` 是金額的小數位數（0 或 2）。

條件不合理時回傳 `400`，內容為 `{"error": "給使用者看的訊息", "field": "欄位名稱"}`；清單欄位為 `名稱:索引`，例如 `prepayPeriod:0`。

範例：

```powershell
Invoke-RestMethod "http://localhost:8080/api/mortgage?loanAmount=10000000&rate=2.2&years=30&graceYears=0&method=EQUAL_PAYMENT"
```

## 計算參考值

計算規則與桌面版 `DEVELOPMENT.md` 的「房貸計算器」「債券計算」兩節相同。以下數值由 `test.bat` 自動檢查，也已在瀏覽器實際操作確認：

| 情境 | 結果 |
| --- | --- |
| 複利預設（原始本金 0、每年投入 20 萬、4%、每年加 1 萬、20 年） | 累積財富 $8,736,140.77（不顯示小數時 $8,736,141） |

## 投資計畫的判斷規則

投入方式：本金在第 1 個月初投入，之後每月月初投入「每月固定投資 + 每月浮動投資」，中途提領在指定月份的月底。目標金額 = 總投入 − 中途提領 + 期望獲利，需要的年化報酬率 r 是讓期滿金額剛好等於目標金額的報酬率，月報酬率為 (1 + r)^(1/12) − 1 逐月複利。只有本金時直接用公式 r =（目標金額 ÷ 本金）^（12 ÷ 月數）− 1；有每月投資或提領時沒有公式解，以二分法求解（累計提領不可超過當時已投入的金額，期滿金額才會隨報酬率遞增、解唯一）。每月浮動投資以區間中間值為「預期」，另外算出「投入上限」與「只投入下限」時需要的報酬率。各類標的的假設只定義在 `bean/InvestmentTier.java`，判斷在 `service/InvestmentPlanner.java`。網頁只顯示結果，不顯示規則表。

定存、公債、公司債依使用者給的區間取中間值為「一般行情」、上限為「行情好」；股票分 5 個等級。依風險由低到高排列：

| 類別 | 一般行情 | 行情好（上限） | 預估波動 | 標的 | 風險 | 建議期間 |
| --- | --- | --- | --- | --- | --- | --- |
| 定存（0.5%～3%） | 1.75% | 3% | 0% | 定存、貨幣市場基金、儲蓄險 | 極低 | 不限 |
| 公債（3%～5%） | 4% | 5% | 4% | 國債、政府公債、公債 ETF | 低 | 1 年以上 |
| 公司債（6%～8%） | 7% | 8% | 8% | 公司債、高收益債、公司債 ETF | 中（信用風險） | 3 年以上 |
| 定存型股票 | 5% | 8% | 12% | 高股息 ETF、金融股、公用事業股（存股） | 中 | 3 年以上 |
| 穩健型股票 | 7% | 12% | 16% | 市值型 ETF、大型權值股 | 中高 | 5 年以上 |
| 穩健成長型股票 | 8% | 14% | 20% | 績優成長股、產業型 ETF | 中高 | 5 年以上 |
| 積極成長型股票 | 10% | 20% | 28% | 中小型成長股、科技股、主題型基金 | 高 | 7 年以上 |
| 高波動型股票 | 12% | 25% | 40% | 題材股、槓桿型 ETF | 很高 | 7 年以上 |
| 高風險投機 | — | — | — | 期貨、選擇權、權證 | 極高 | 短線操作 |
| 只能靠運氣 | — | — | — | 大樂透、威力彩等彩券 | 幾乎必定虧損 | — |

1. **可考慮的方案**：從風險最低、行情好時達得到的類別往上找；風險較高的類別報酬不一定較高（ex. 定存型股票低於公司債），行情好也達不到的略過。標示「一般行情可達成」或「需行情較好」，投資期間短於建議期間時另標「期間短於建議」。
2. **列到哪裡為止**：列到第一個「一般行情可達成、且期間足夠」的類別，再多列一類，最多 4 個方案。例如需要 4.56%、5 年：公債（需行情較好）、公司債、定存型股票。期望獲利為 0 時只列定存。
3. **資產配置（自動搜尋）**：使用者不必自己填比例。定存、公債、公司債、股票以每 5% 一級列出所有組合，股票部位再從該型可用的股票等級中選一種，依股票比例分成三型（定義在 `bean/AllocationProfile.java`）：

   | 類型 | 股票比例 | 定存上限 | 公司債上限 | 可用的股票等級 | 組合數 | 建議期間 |
   | --- | --- | --- | --- | --- | --- | --- |
   | 保守型 | 0%～25% | 50% | 20% | 定存型、穩健型 | 605 | 1 年以上 |
   | 穩健型 | 30%～45% | 30% | 30% | 定存型、穩健型、穩健成長型 | 585 | 3 年以上 |
   | 積極型 | 50%～100% | 20% | 30% | 穩健型、穩健成長型、積極成長型、高波動型 | 840 | 5 年以上 |

   - 上限與股票等級的限制讓配置符合該型的性質：沒有限制時，公司債（7%、波動 8%）會壓過股票，積極型會變成 90% 公司債，保守型也會混進高波動股；6%～8% 的公司債有信用風險，不宜集中。定存上限避免目標很容易時配置變成「定存 70%」這種組合。
   - 報酬率依比例加權。預估波動 = √(Σ 比例ᵢ × 比例ⱼ × 波動ᵢ × 波動ⱼ × 相關係數ᵢⱼ)，相關係數：公債與公司債 0.5、公債與股票 0.1、公司債與股票 0.5，定存視為沒有波動。
   - **兩階段挑選**：共 2,030 種組合，全部模擬太慢，先以近似公式估計達成機率（把期滿金額視為對數常態分布，中位數為一般行情的逐月複利金額（已扣除提領），變異以各筆投入依期滿價值加權的平均剩餘年數計算；逐年調整比例時用整個期間的平均比例），每型取機率最高的 15 種，加上與最高者相差 6 個百分點內波動最低的 20 種，再做蒙地卡羅模擬。一般情境在伺服器約 20～60 毫秒，100 年約 130 毫秒。
   - **蒙地卡羅模擬**（`service/MarketSimulator.java`）：定存、公債、公司債、股票**分別模擬** 500 種市場走勢。每類標的每年報酬為對數常態分布，ln(1 + 年報酬) ~ N(ln(1 + 一般行情報酬率), 波動²)，所以一般行情就是中位數；三個市場因子（公債、公司債、股票）以 Cholesky 分解產生上述相關係數，5 個股票等級共用股票因子，定存沒有波動。每年的成長平均分攤到每個月、每月月初依當年比例投入；年度之間依設定再平衡（`service/Allocation.java`）。一組市場走勢先算好每段的成長倍數，2,000 多種配置只需乘加，不必重算指數。所有配置使用同一組亂數（相同的市場情境）比較才公平；種子固定，相同條件每次結果相同，伺服器與 GitHub Pages 也相同。
   - **模擬設定**（網頁上的「模擬設定」與「中途提領」）：

     | 設定 | 選項 | 作用 |
     | --- | --- | --- |
     | 目前年齡 | 預設 35 歲 | 年齡法則的股票上限；說明文字列出現在與期滿時的建議股票比例 |
     | 配置調整 | 固定比例／接近期滿逐年降低股票／依年齡法則 | 目標日期：期滿前 5 年起（期間較短時從第 2 年）每年把股票移到公債，最後一年降到起始的一半；年齡法則：股票 ≤ 100 − 當年年齡，搜尋時起始比例超過上限的配置不列入（60 歲時積極型沒有可用配置）。兩者每年依新比例調整 |
     | 再平衡 | 每年／偏離超過 5 個百分點才調整／不再平衡 | 每年初檢查；不再平衡時漲多的資產比例會越來越高，每月投資仍依設定比例分配 |
     | 報酬分布 | 常態／厚尾 | 厚尾為自由度 5 的多變量 t 分布（三個因子同除以一個卡方亂數，標準差仍為 1），極端年份較多、且容易一起跌；兩者用同一組亂數。單年衝擊限制在 ±6 個標準差 |
     | 壓力測試 | 金融海嘯／升息循環／長期盤整，發生在期滿前／期間中段／剛開始投資時 | 情境年份的報酬換成情境數值（`bean/StressScenario.java`；長期盤整連續 5 年只降低一般行情、仍有波動），其他年份與一般模擬相同的走勢，列出三型在情境下的達成機率與金額 |
     | 中途提領 | 第幾個月底、金額，最多 20 筆 | 依各資產比例賣出；付不出來的走勢視為未達成。獲利 = 期滿金額 + 提領 − 總投入 |

   - **策略比較**：三型的最佳配置再分別以 5 種方式模擬（固定比例不再平衡／每年再平衡／偏離時再平衡、接近期滿逐年降低股票、年齡法則），列出達成機率、中位數與悲觀金額，並指出目前設定是否最好（差距 2 個百分點內視為模擬誤差）、哪種方式的悲觀金額最高。
   - **每型的最佳配置**：模擬的達成機率與該型最高者相差不到 2 個百分點（機率很低時最多為最高機率的 1/4）的配置中，取預估波動最低的；500 次模擬的誤差約 ±2 個百分點，不值得為了更小的差距多承擔風險。機率都是 0 時取一般行情報酬最高、最接近目標的。同時列出期滿金額的第 10 百分位（悲觀）、中位數與第 90 百分位（樂觀）。
   - **建議哪一型**：期間足夠且達成機率 75% 以上 → 期間足夠且 50% 以上（以上兩級取最保守的一型）→ 期間足夠中機率最高 → 不看期間機率最高；三型的機率都是 0 時提醒延長期間、增加投入或調整目標。
   - 評估標籤：機率 75% 以上「把握高」、50% 以上「有機會」、25% 以上「需行情較好」、其他「不太可能」。頁面只列出三型挑中的配置。「可考慮的方案」卡片也用同樣的模擬顯示各類標的的達成機率。
   - **逐年試算**（三型各一張表）：本金與每月投資依當年配置比例分到定存、公債、公司債、股票，各自以一般行情報酬率逐月複利，並依模擬設定再平衡、調整比例與提領；每年列出累積投入（有提領時加列累積提領）、四種資產各自的金額與累積獲利（再平衡只搬動金額、不改變獲利）、總金額、累積獲利，並對照「目標進度」（以需要的年化報酬率計算、剛好在期滿達標的金額）。總金額達到目標進度時顯示為主色，落後時為紅色。
   - 例如 100 萬、5 年、獲利 25 萬（需要 4.56%，預設每年再平衡）：保守型 0／60／20／20（股票用穩健型，達成機率 63%，建議）、穩健型 0／40／30／30（穩健成長型股票，70%）、積極型 0／25／25／50（積極成長型股票，71%）。保守型每年再平衡時整體以 5.2% 成長，第 5 年：公債 100 萬 × 1.052⁴ × 60% × 1.04、公司債與股票各 100 萬 × 1.052⁴ × 20% × 1.07。
4. **期間不足**：風險最低的方案期間不足時，提醒短期波動並算出「延長到建議年數後需要的年化報酬率」。年數夠長時，總報酬 100%～200% 也會落在穩健型以上的股票等級。
5. **每月浮動投資**：只投入下限時需要的報酬率若落到風險更高的類別（或下限為 0 而沒有投入任何資金），提出警示；方案卡片也會標示「浮動投資只投入下限時不足」。
6. **不可行**：連高波動型股票的上限 25% 都達不到時為高風險投機（可能不可行）；需要的年化與總報酬率都超過 100% 時只能靠運氣（不可行）。另以穩健型股票一般行情 7% 估算延長期間、增加本金、增加每月投資、降低目標四種替代方案（其他條件不變）。總報酬也要超過 100% 才算彩券，避免「1 個月賺 10%」這類短期目標年化後超過 100% 而被誤判。
7. 這些報酬率都是假設值，頁面上也註明不是個人化的投資建議。

## 樂透投資的計算規則

彩券規則只定義在 `bean/LotteryGame.java`，計算在 `service/LotteryCalculator.java`。規則以台灣彩券公告為準，改版時只要改 `LotteryGame`。

| 彩券 | 每注 | 開獎 | 玩法 | 頭獎機率 | 獎金 |
| --- | --- | --- | --- | --- | --- |
| 今彩539 | 50 元 | 每週一至週六 | 1～39 選 5 個 | 1/575,757 | 全部固定：頭獎 800 萬（每期總額上限 2,400 萬）、貳獎 2 萬、參獎 300、肆獎 50 |
| 大樂透 | 50 元 | 每週二、五 | 1～49 選 6 個，另開特別號 | 1/13,983,816 | 總獎金為銷售額 56%：伍獎 2,000、陸獎 1,000、柒獎 400、普獎 400 固定，其餘依頭獎 82%、貳獎 6.5%、參獎 7%、肆獎 4.5% 分配；頭獎保底 1 億 |
| 威力彩 | 100 元 | 每週一、四 | 第 1 區 1～38 選 6 個、第 2 區 1～8 選 1 個 | 1/22,085,448 | 總獎金為銷售額 55%：參獎 15 萬、肆獎 2 萬、伍獎 4,000、陸獎 800、柒獎 400、捌獎 200、玖獎 100、普獎 100 固定，其餘依頭獎 89%、貳獎 11% 分配；頭獎保底 2 億 |

1. **期望回報率** = Σ（各獎項中獎機率 × 每注獎金）÷ 每注價格。中獎機率 = 中獎組合數 ÷ 所有組合數，例如大樂透參獎（中 5 個）為 C(6,5) × 42 ÷ C(49,6) = 1/55,491。
2. **獎金池的獎項**以長期平均估算：平均獎金 =（每注價格 × 支出率 × 所有組合數 − 固定獎金總額）× 分配比率 ÷ 中獎組合數。無人中獎時累積到下期，長期來看都會發出去，所以稅前回報率剛好等於支出率（大樂透 56%、威力彩 55%）。使用者輸入頭獎金額時只改變頭獎（未計入多人同時中獎平分），不可低於保底。
3. **稅**：單注獎金超過 5,000 元扣 20% 所得稅與 0.4% 印花稅（5,000 元以下免稅），稅後回報率：今彩539 47.76%、大樂透 50.52%、威力彩 47.56%。
4. **定期買入**：每次買入金額 ÷ 每注價格無條件捨去為注數；一年以 52 週計算，每期都買時今彩539 一年 312 次、大樂透與威力彩 104 次。期間內預計中獎次數 = 總注數 × 機率，至少中一次的機率 = 1 −（1 − 機率）^總注數。
5. **中幾個才回本**：只靠同一個獎項，要中 ⌈總投入 ÷ 稅後獎金⌉ 個；例如大樂透每期 200 元、10 年（投入 $208,000）：頭獎 1 個、貳獎 1 個、參獎 6 個、肆獎 20 個、普獎 520 個。中到這麼多個的機率為二項分布 B(總注數, 中獎機率) 至少 k 次的機率：標準差超過 2,000 時以常態近似，中獎機率低於 1% 時以卜瓦松近似，其餘逐項累加。獎金不到每注價格時不可能回本，剛好等於時要每一注都中。
6. **模擬**：2,000 人各買同樣的總注數，各獎項的中獎次數依序以條件二項分布抽出（每注只中一個獎項；平均次數少於 30 時精確抽樣，否則以常態近似），獎金池獎項以長期平均計算。列出稅後中獎總額的中位數、最差 10%、最好 10% 與沒有虧損的比例。種子固定，相同條件結果相同。
7. **對照的定期投資**：每次買彩券時改把同樣的錢投入，年報酬率依買入次數換算成每期報酬複利。
8. 未計入：加碼活動、熱門號碼時普獎改為均分、今彩539 頭獎上限的平分。

## 貨幣投資的計算規則

計算在 `service/TimeDepositCalculator.java`，參數與輸出在 `web/api/CurrencyApi.java`。

1. **換匯**：金額 × 原幣別匯率 ÷ 目標幣別匯率（匯率都是 1 單位可換多少新台幣），四捨五入到小數兩位，就是定存本金。
2. **依序定存**：第 1 筆從第 1 個月開始，到期後接著存下一筆。每筆利息 = 本金 × 年利率 × 月數 ÷ 12，四捨五入到小數兩位。每筆各自選到期後的方式：本息續存時下一筆的本金 = 這一筆的到期本息；本金續存時下一筆的本金與這一筆相同，利息領出不再計息，最後與本金一起換回。最後一筆到期後直接換回，所以最後拿回的一定是原來的本金加全部利息。例如 USD 31,250 先存 3 個月 4%（本金續存，領出 312.50）、再 3 個月 4%（本息續存）、再 6 個月 4%：第 3 筆本金 31,562.50，利息合計 1,256.25。
3. **換回**：到期本息 × 到期預估匯率（1 單位定存幣別可換多少換回貨幣）。本金與利息分別換算，匯兌損益 = 本金換回 − 投入成本，利息收益 = 利息換回。
4. **投入成本** = 原來的金額依目前匯率換成換回貨幣（換回貨幣就是原幣別時就是原來的金額）。總報酬 = 換回金額 − 投入成本；年化報酬率 =（換回金額 ÷ 投入成本）^（12 ÷ 總月數）− 1。
5. **損益兩平匯率** = 投入成本 ÷ 到期本息，到期匯率高於它就不會虧損。
6. **到期匯率變動試算**：目前匯率 −10%、−5%、−3%、0、+3%、+5%、+10%，加上預估匯率與損益兩平匯率，由低到高列出換回金額與報酬；相差不到百萬分之一的匯率合併成一列。換回貨幣與定存幣別相同時沒有匯率風險，不列這張表。
7. 網頁的「到期預估匯率」預設跟著目前匯率，自行輸入後就不再自動改變，按「帶入目前匯率」可恢復。
8. **線上匯率**：按「取得最新匯率」時由瀏覽器直接讀取「國際匯率服務」[ExchangeRate-API](https://www.exchangerate-api.com)（`open.er-api.com`）或「開源匯率資料」[Currency API](https://github.com/fawazahmed0/exchange-api)（jsDelivr，連不上時改用 `currency-api.pages.dev`），兩者都免金鑰、允許跨網域讀取，所以 GitHub Pages 版也能用；選的來源連不上時自動改用另一個。讀到的是「1 新台幣可換多少外幣」，換成「1 外幣可換多少新台幣」並取 6 位有效數字，填入畫面上的匯率，之後換幣別或恢復預設時也用這組匯率（債券計算也是）。這是買賣中間價的參考匯率，與銀行牌告的買入、賣出匯率不同。
9. 未計入：利息所得稅、換匯手續費、銀行買賣匯差、依實際天數（365 或 360 天）計息的差異。

## 資料保存

| 鍵（localStorage） | 內容 |
| --- | --- |
| `fm.theme`、`fm.font` | 外觀設定 |
| `fm.page` | 上次開啟的分頁 |
| `fm.form.分頁` | 該分頁的試算條件（JSON，含保存時間 `savedAt`），每次試算時寫入 |
| `fm.rates`、`fm.rateSource` | 貨幣投資上次線上取得的匯率（來源、資料時間、取得時間）與選擇的匯率來源 |

用 localStorage 而不是 cookie：

- **沒有到期日**，不需要設定保留天數，會一直保留到使用者清除網站資料（因此超過 180 天）。cookie 必須設定期限，而且 Safari 對網頁程式寫入的 cookie 最多只保留 7 天。
- 資料只存在使用者自己的裝置，不會隨每個請求送到伺服器；GitHub Pages 版也不能由伺服器寫入 cookie。
- 容量約 5 MB，cookie 只有約 4 KB，房貸清單最多 240 筆可能放不下。

瀏覽器本身的限制（cookie 也一樣受限，無法由網站避開）：

- 無痕／私密瀏覽：關閉視窗後清除。
- Safari（iPhone、iPad、Mac）：使用 Safari 期間連續 7 天沒有開啟本網站，會刪除網站寫入的資料。加入主畫面的網頁不受此限。
- 使用者手動清除瀏覽資料，或瀏覽器設定為關閉時清除網站資料。
- 同一台電腦的其他人也看得到上次的試算條件；共用電腦可按「恢復預設」。

## 安全性

- 回應附 Content-Security-Policy（只允許同源的 script、style；連線只允許同源與兩個線上匯率來源）、`X-Content-Type-Options`、`X-Frame-Options`。
- 靜態檔只開放白名單副檔名，拒絕 `..`、反斜線等路徑。
- 數字只接受一般寫法、最多 13 位整數與 8 位小數，避免極端輸入耗盡 BigDecimal 運算資源；請求內容上限 64 KB；清單最多 120 筆。

## 已知限制

- 幣別的預設匯率只是範例；線上匯率只在按下「取得最新匯率」時讀取，是參考中價，不是銀行的買入／賣出牌告。
- 沒有帳號，試算條件只保存在各自的瀏覽器，換裝置或換瀏覽器看不到（見「資料保存」）。
- 內建 HttpServer 適合個人或內部使用；對外公開時建議放在 Nginx、IIS 等反向代理之後並啟用 HTTPS。
- 網站執行中無法重新建置（jar 檔被占用），請先 `Ctrl+C` 停止。
- GitHub Pages 版第一次開啟要多下載約 240 KB 的試算引擎（壓縮傳輸後較小）。
